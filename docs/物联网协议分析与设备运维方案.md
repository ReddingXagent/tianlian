## 二、核心协议详解与运维映射

### 2.1 CAN 总线协议（电池/充电模块）

**硬件型号**: EAST PCS-125 (125kW储能变流器), EAST BESS-261 (261kWh电池)

**协议特征**:
- 物理层: CAN 2.0B, 500kbps
- 帧格式: 标准11位ID / 扩展29位ID
- 通信模式: 主从轮询 + 事件触发

**运维数据点**:

| 数据类别 | CAN帧ID | 字段 | 运维意义 | 故障阈值 |
|----------|---------|------|----------|----------|
| **电池状态** | 0x351 | SOC (0-100%) | 充放电策略 | <20% 告警, <10% 切断 |
| **电池状态** | 0x351 | SOH (0-100%) | 电池健康度 | <80% 预警更换 |
| **电池状态** | 0x352 | 总电压 (DC 600-800V) | 系统安全 | 过压>850V/欠压<550V |
| **电池状态** | 0x352 | 总电流 (±125kW/800V) | 功率监控 | 过流>160A |
| **温度** | 0x353 | 电芯温度 (×16) | 热管理 | >45℃ 降功率, >55℃ 停机 |
| **绝缘** | 0x354 | 绝缘电阻 | 安全 | <1MΩ/kV 告警 |
| **故障码** | 0x355 | DTC码 | 故障诊断 | 按GB/T 31465解析 |

**故障诊断流程**:

```
CAN帧异常 → 解析DTC码 → 匹配故障库 → 分级处理
    │
    ├─ P0 (紧急): 过温/过压/绝缘故障 → 立即停机 + 告警推送
    ├─ P1 (严重): 单体电压不一致 → 降功率 + 工单派发
    ├─ P2 (一般): SOC校准偏差 → 记录 + 下次维护处理
    └─ P3 (提示): 温度偏高趋势 → 加强监控 + 预测性维护
```

**修复策略**:
1. **软件修复**: CAN参数远程下发 (如SOC校准、保护阈值调整)
2. **半自动修复**: 远程重启BMS/PCS模块
3. **现场修复**: 生成工单 + 故障码 + 更换模块指引

### 2.2 Modbus-RTU 协议（电表/仪表）

**硬件型号**: 防逆流计量表 (Class 0.5S精度, RS485)

**协议特征**:
- 物理层: RS485, 9600bps, 8N1
- 功能码: 0x03 (读保持寄存器), 0x04 (读输入寄存器), 0x10 (写多寄存器)
- 通信模式: 主站轮询 (1-2s周期)

**运维数据点**:

| 寄存器地址 | 数据类型 | 含义 | 运维意义 |
|-----------|----------|------|----------|
| 0x0000-0x0001 | UINT32 | 正向有功电能 (kWh) | 计费/结算 |
| 0x0002-0x0003 | UINT32 | 反向有功电能 (kWh) | 防逆流检测 |
| 0x0100 | INT16 | A相电压 (0.1V) | 电网质量 |
| 0x0101 | INT16 | B相电压 (0.1V) | 电网质量 |
| 0x0102 | INT16 | C相电压 (0.1V) | 电网质量 |
| 0x0110 | INT16 | A相电流 (0.01A) | 负载监控 |
| 0x0120 | INT32 | 有功功率 (W) | 实时功率 |
| 0x0130 | INT16 | 功率因数 (0.001) | 电能质量 |

**运维应用场景**:

1. **防逆流检测**: 反向有功 > 0 → 立即降低充电功率或启动储能放电
2. **电能质量监控**: 电压偏差 > ±10% → 告警 + 记录
3. **负载预测**: 基于有功功率趋势 → 动态调整储能充放电策略

**故障诊断**:
- Modbus超时 → 检查RS485线路/终端电阻
- CRC校验失败 → 电磁干扰排查
- 数据跳变 → 传感器故障诊断

### 2.3 OCPP 1.6J 协议（充电桩）

**硬件型号**: EAST DC-600 (600kW充电堆), 8×GB/T双枪终端 + CCS1/CCS2终端

**协议特征**:
- 传输层: WebSocket (ws://host:80/ocpp/chargepoint)
- 数据格式: JSON, 基于JSON Schema验证
- 安全: WSS (TLS 1.2+) 可选
- 版本: OCPP 1.6J (JSON版)

**核心Action与运维映射**:

| Action | 方向 | 运维用途 |
|--------|------|----------|
| **BootNotification** | CP → CS | 设备上线/重启告警, 版本检查 |
| **Heartbeat** | CP → CS | 在线状态监控 (30s间隔) |
| **StatusNotification** | CP → CS | 充电枪状态变化 (Available/Occupied/Charging/Faulted) |
| **MeterValues** | CP → CS | 实时计量数据 (电压/电流/功率/电量) |
| **DiagnosticsStatusNotification** | CP → CS | 诊断数据上传状态 |
| **FirmwareStatusNotification** | CP → CS | 固件升级进度 |
| **RemoteStartTransaction** | CS → CP | 远程启动充电 |
| **RemoteStopTransaction** | CS → CP | 远程停止充电 |
| **Reset** | CS → CP | 远程重启 (Soft/Hard) |
| **GetDiagnostics** | CS → CP | 远程获取诊断日志 |
| **UpdateFirmware** | CS → CP | 远程固件升级 |
| **ClearCache** | CS → CP | 清除本地缓存 |

**故障诊断 - StatusNotification 状态机**:

```
Available → Occupied → Preparing → Charging → SuspendedEV/SuspendedSE → Finishing → Available
    │           │           │            │                                    │
    │           │           │            │                                    └─ 正常结束
    │           │           │            └─ 车辆/SE暂停 (车辆BMS指令/定时器)
    │           │           └─ 握手阶段 (CC信号/PWM检测)
    │           └─ 插枪但未启动 (等待支付/预约)
    └─ 空闲待机

异常分支:
    → Faulted (需要远程Reset或现场维修)
    → Unavailable (离线/断电)
```

**运维自动化策略**:

```python
# 基于OCPP状态机的自动运维逻辑
def handle_status_notification(status, info):
    if status == "Faulted":
        # 1. 尝试远程Reset
        send_reset(chargepoint_id, type="Soft")
        
        # 2. 等待30秒后检查状态
        if wait_status(30) == "Faulted":
            # 3. 尝试Hard Reset
            send_reset(chargepoint_id, type="Hard")
            
            # 4. 仍失败则生成工单
            create_workorder(
                device=chargepoint_id,
                fault=info,
                priority="P1",
                actions=["现场检修", "模块更换"]
            )
    
    elif status == "SuspendedEV":
        # 车辆侧暂停 - 记录日志, 不干预
        log_suspension(chargepoint_id, info)
    
    elif status == "Unavailable":
        # 设备离线 - 检查网络
        if not ping(chargepoint_id):
            alert_network_issue(chargepoint_id)
```

### 2.4 IEC 104 协议（EMS能量管理系统）

**硬件型号**: EAST EMS-1000

**协议特征**:
- 传输层: TCP/IP, 端口 2404
- 应用层: IEC 60870-5-104 (平衡式传输)
- 通信模式: 主站轮询 + 从站主动上送
- 数据类型: 遥测(YC)、遥信(YX)、遥控(YK)、遥调(YT)

**运维数据点**:

| 类型 | 信息对象地址 | 含义 | 运维用途 |
|------|-------------|------|----------|
| **YC (遥测)** | 1001-1010 | 电池SOC/SOH/电压/电流/温度 | 实时状态监控 |
| **YC (遥测)** | 1011-1020 | 充电功率/放电功率/网侧功率 | 能量调度 |
| **YC (遥测)** | 1021-1030 | 各充电枪实时功率 | 负载均衡 |
| **YX (遥信)** | 2001-2010 | 断路器状态/接触器状态 | 设备状态 |
| **YX (遥信)** | 2011-2020 | 告警信号/保护动作 | 故障告警 |
| **YK (遥控)** | 3001-3005 | 断路器分合/接触器控制 | 远程操作 |
| **YT (遥调)** | 4001-4005 | 充电功率设定/放电功率设定 | 策略下发 |

**EMS运维策略**:

1. **削峰填谷**: 基于电价时段自动切换充放电模式
2. **防逆流**: 实时监测网侧功率, 反向>0时立即降低充电功率
3. **需求响应**: 接收调度中心指令, 动态调整功率输出
4. **电池保护**: SOC上下限控制, 温度保护联动

### 2.5 MQTT 协议（云平台数据通道）

**架构**: MQTT over WebSocket (443端口, 防火墙友好)

**Topic 设计**:

```
tianlian/v3/{station_id}/{device_id}/telemetry      # 遥测数据上报
tianlian/v3/{station_id}/{device_id}/alarm          # 告警上报
tianlian/v3/{station_id}/{device_id}/status         # 状态变更
tianlian/v3/{station_id}/{device_id}/command        # 远程控制指令
tianlian/v3/{station_id}/{device_id}/command/ack    # 指令确认
tianlian/v3/{station_id}/{device_id}/diagnostics    # 诊断数据
tianlian/v3/{station_id}/heartbeat                  # 站点心跳
```

**消息格式示例 (遥测上报)**:

```json
{
  "station_id": "ST-001",
  "device_id": "BMS-001",
  "timestamp": 1714656000000,
  "data": {
    "soc": 78.5,
    "soh": 95.2,
    "voltage": 720.5,
    "current": -45.2,
    "temperature": [32.1, 33.5, 31.8, 34.2],
    "fault_code": 0
  }
}
```

**运维价值**:
- 实时数据汇聚: 所有设备数据统一MQTT通道
- 告警即时推送: QoS 1保证不丢
- 远程控制: 指令下发 + ACK确认机制
- 边缘协同: 支持断网缓存(QoS 2)

### 3.2 设备健康度评估模型

**4维度12指标体系** (参考天链2.0健康度引擎设计):

| 维度 | 指标 | 权重 | 数据来源 | 评分规则 |
|------|------|------|----------|----------|
| **通信状态** | 在线率 | 15% | MQTT心跳 | >99%=100, >95%=80, <95%线性递减 |
| **通信状态** | 数据完整率 | 10% | Modbus轮询 | 无丢包=100, 每丢1%=减5分 |
| **电气性能** | 电压偏差 | 15% | CAN/IEC104 | ±5%=100, ±10%=60, >±10%=0 |
| **电气性能** | 功率因数 | 10% | Modbus电表 | >0.95=100, >0.9=80, <0.9线性递减 |
| **电气性能** | 效率 | 10% | 输入/输出功率 | >95%=100, >90%=80, <90%线性递减 |
| **安全状态** | 告警次数 | 15% | OCPP/MQTT告警 | 0次=100, 每1次减10分 |
| **安全状态** | 故障次数 | 10% | 工单系统 | 0次=100, 每1次减15分 |
| **安全状态** | 绝缘电阻 | 5% | BMS CAN帧 | >100MΩ=100, <10MΩ=0 |
| **电池健康** | SOH | 15% | BMS CAN帧 | >90%=100, >80%=80, <80%线性递减 |
| **电池健康** | 温度均衡性 | 5% | BMS温度数组 | 温差<5℃=100, >15℃=0 |
| **维护记录** | 维护及时性 | 5% | 工单系统 | 按时=100, 逾期=50 |
| **维护记录** | 修复质量 | 5% | 工单评价 | 无返修=100, 有返修=50 |

**健康度分级**:
- 🟢 **健康** (90-100): 正常运行
- 🟡 **注意** (70-89): 关注趋势, 预防性维护
- 🟠 **警告** (50-69): 计划检修, 降功率运行
- 🔴 **危险** (<50): 立即停机, 紧急维修

### 3.3 告警分级与响应机制

| 级别 | 条件 | 响应时间 | 通知方式 | 处理流程 |
|------|------|----------|----------|----------|
| **P0 紧急** | 过温/过压/绝缘故障/火灾 | <5分钟 | IM+电话+短信 | 自动停机 → 告警推送 → 工单自动派发 |
| **P1 严重** | 通信中断/充电模块故障/BMS告警 | <30分钟 | IM+短信 | 远程诊断 → 尝试恢复 → 工单派发 |
| **P2 一般** | 电能质量异常/效率下降 | <4小时 | IM | 记录分析 → 计划维护 |
| **P3 提示** | 趋势异常/维护到期 | <24小时 | IM | 记录 → 下次维护窗口处理 |

## 四、故障诊断与修复流程

### 4.1 故障诊断决策树

```
设备异常
    │
    ├── 通信故障?
    │   ├── CAN总线无数据 → 检查CAN收发器/终端电阻
    │   ├── Modbus超时 → 检查RS485线路/地址配置
    │   ├── OCPP断连 → 检查网络/WebSocket连接
    │   └── IEC104中断 → 检查TCP连接/对端状态
    │
    ├── 电气故障?
    │   ├── 过压/欠压 → 检查电网质量/变压器
    │   ├── 过流 → 检查负载/短路
    │   ├── 绝缘下降 → 检查线缆/接头/潮湿
    │   └── 功率因数异常 → 检查无功补偿
    │
    ├── 电池故障?
    │   ├── SOC跳变 → 校准/检查电流传感器
    │   ├── SOH下降 → 评估寿命/考虑更换
    │   ├── 温差过大 → 检查冷却系统/电芯一致性
    │   └── 单体过压 → BMS保护/检查均衡电路
    │
    ├── 充电故障?
    │   ├── 握手失败 → 检查CC/PWM信号/车辆BMS
    │   ├── 充电中断 → 检查急停/门禁/通信
    │   ├── 功率不足 → 检查模块数量/散热
    │   └── 计量异常 → 检查电表/CT极性
    │
    └── 热管理故障?
        ├── 温度过高 → 检查风扇/空调/散热片
        ├── 温度传感器异常 → 校准/更换传感器
        └── 冷却液泄漏 → 现场检查/停机维修
```

### 4.2 远程修复能力矩阵

| 故障类型 | 远程修复 | 修复方式 | 成功率 |
|----------|----------|----------|--------|
| 通信中断 | ✅ | 远程重启通信模块 | 70% |

def auto_create_workstation(event):
    """
    根据设备事件自动生成运维工单
    """
    if event.type == "CAN_FAULT" and event.dtc_code in CRITICAL_DTC:
        return WorkOrder(
            device=event.device_id,
            fault=f"CAN DTC: {event.dtc_code}",
            priority="P1",
            auto_assign=True,
            suggested_actions=get_suggested_actions(event.dtc_code),
            diagnostic_data={
                "can_frames": event.recent_frames,
                "voltage": event.voltage,
                "temperature": event.temperature,
                "soc": event.soc
            }
        )
    
    elif event.type == "OCPP_STATUS" and event.status == "Faulted":
        return WorkOrder(
            device=event.chargepoint_id,
            fault=f"OCPP Faulted: {event.info}",
            priority="P1",
            auto_assign=True,
            suggested_actions=["远程Reset", "检查充电模块", "更换枪线"],

                "ocpp_logs": get_ocpp_logs(event.chargepoint_id),
                "meter_values": get_recent_meter_values(event.chargepoint_id)
            }
        )
    
    elif event.type == "HEALTH_DEGRADED" and event.health_score < 50:
        return WorkOrder(
            device=event.device_id,
            fault=f"健康度降至 {event.health_score}",
            priority="P2",
            auto_assign=False,
            suggested_actions=["计划检修", "电池检测", "模块更换评估"],

```typescript
// 协议适配层 - 统一数据模型
interface DeviceTelemetry {
  deviceId: string;
  stationId: string;
  timestamp: number;
  protocol: 'CAN' | 'MODBUS' | 'OCPP' | 'IEC104' | 'MQTT';
  data: {
    // 通用字段
    online: boolean;
    healthScore: number;
    
    // 设备类型特定字段
    battery?: {
      soc: number;
      soh: number;
      voltage: number;
      current: number;
      temperature: number[];
      faultCode: number;
    };
    charging?: {
      status: string;
      power: number;
      energy: number;
      voltage: number;
      current: number;
    };
    grid?: {
      voltage: number[];
      current: number[];
      activePower: number;
      reactivePower: number;
      powerFactor: number;
    };
  };
}

// 协议解析器接口
interface ProtocolParser {
  parse(rawData: Buffer): DeviceTelemetry;
  validate(data: DeviceTelemetry): boolean;
  normalize(data: DeviceTelemetry): DeviceTelemetry;
}
```

### 5.3 数据流实现路径

```
1. 设备数据采集
   ├── CAN: 通过CAN转Ethernet网关 (如Moxa NPort 5232)
   ├── Modbus: RS485转Ethernet网关
   ├── OCPP: 充电桩直连云平台WebSocket
   └── IEC104: EMS直连调度中心

2. 协议解析
   ├── 边缘网关: 本地协议解析 + 数据标准化
   └── 云平台: 统一数据模型入库

3. 实时监控
   ├── MQTT订阅: 实时数据推送到Dashboard
   ├── WebSocket: 前端实时刷新
   └── 告警引擎: 阈值匹配 + 分级推送

4. 故障诊断
   ├── 规则引擎: 故障码 → 诊断结果
   ├── 趋势分析: 健康度变化趋势
   └── AI辅助: 历史故障模式匹配

5. 修复执行
   ├── 远程: OCPP Reset / IEC104遥控 / 参数下发
   ├── 工单: 自动生成 + 智能派发
   └── 验证: 修复后数据回传确认
```
