# 前端大版本升级预研 — React 18→19 / Vite 5→7+ / react-router 7→8

> 状态: 预研 v1.0 (2026-07-31, 大圣)
> 背景: D7安全卡发现 react-router RSC CSRF (high×2, GHSA-qwww-vcr4-c8h2) 仅 8.3.0 修复，升 8 须连带 React 19 + Vite 7。当前决策=风险接受(纯客户端 SPA 不可利用)，本预研评估根治升级的成本。

## 2. React 18→19 代码面扫描 (src/ 511 个 ts/tsx 实测)

| Breaking 标记 | 命中 | 结论 |
|---|---|---|
| forwardRef | **0** | ref-as-prop 迁移零成本 |
| ReactDOM.render (legacy) | **0** | 已 createRoot (main.tsx 1 处) |
| defaultProps | **0** | 无函数组件 defaultProps 移除影响 |
| findDOMNode | **0** | 无 |
| UNSAFE_ / componentWillMount / componentWillReceiveProps | **0** | 无遗留生命周期 |
| useContext | 2 | API 不变, 无影响 |

**结论: 我方代码对 React 19 的 breaking 暴露面≈0。** 主要工作量在:
- @types/react 19 的 TS 类型收紧 (ReactNode 不再隐式含 undefined、JSX 命名空间改 React.JSX、泛型推断变化) → tsc --noEmit 驱动逐文件修, 机械性工作
- 第三方库 peer 连带 (见 §1 表: fiber 9 / drei 10 / antd ≥5.22 / react-i18next 15)

## 3. 路由面扫描 (react-router 7→8)

- `<Route>` 组件: 172 处 | useNavigate: 40 | useLocation: 13
- 用法全为**声明式 SPA 模式** (BrowserRouter + Routes), 零 loader/action、零 unstable_* RSC API
- react-router 8 对纯声明式 SPA 的 breaking 面小; 主要动作是 `react-router-dom` 包名 → `react-router` (dom 包在 v7+ 已是再导出 shim, v8 建议直接换)
- CSRF advisory (GHSA-qwww-vcr4-c8h2) 影响 RSC/framework 模式 → 我方不可利用, 升 8 是"根治性"而非"应急性"

## 4. Vite 5→7 要点 (建议 5→7 先, 8 观望)

- Node 要求提升 (本机 v24 已满足; 生产构建在本机, 无 CI 环境差异)
- CJS (require) 构建产物移除 → 确认 vite.config.ts 及所有插件走 ESM (本项目 "type": "module" ✓)
- @vitejs/plugin-react 4→6 连带
- CSS 默认导入行为 / postcss 配置细节变化 → 逐项核 vite.config.ts
- vitest 4.1.7 已兼容 vite 7 (vite 8 支持待 vitest 官方跟进 → **这是建议先 7 不直跳 8 的主因**)
- vite-plugin-pwa 1.3.0 对 vite 7 兼容性需实施时验证

## 5. 耦合关系与推荐顺序

```
Phase A: React 18→19  (@types/react 19 + antd→5.22+ + fiber→9 + drei→10 + react-i18next→15)
         门禁: tsc --noEmit 零错误 + vitest 全量 + 3D 可视化页(2文件)手工冒烟
Phase B: Vite 5→7    (plugin-react→6, TS→5.6+, vite.config 逐项核)
         门禁: build 成功 + vitest 全量 + playwright e2e 主路由
Phase C: react-router-dom 7 → react-router 8 (换包名 + import 批量替换)
         门禁: playwright e2e 全量 (172 路由抽样冒烟清单)
```

三相位**独立可交付**, 任一相位失败可单独回滚, 不互相绑架。

## 6. 回归测试策略

- 每相位: `vitest run` 全量 (单元) + `tsc --noEmit` (类型)
- Phase B/C 追加: `playwright test` e2e (已有 test:e2e 基建)
- 主路由冒烟清单: 登录 → 监控大盘 → 站点详情 → 工单 → 报表 → 3D 可视化 (fiber 升级重点) → 富文本编辑页 (quill)

## 8. 升/不升建议

**建议: 可升, 但非紧急, 排期 P2。**

- RSC CSRF 对我方**始终不可利用** (零 RSC 用法), 风险接受决策长期有效, 不升也没有安全敞口
- 升级收益: 解锁 react-router 8 安全线 + React 19 性能 (自动 memo/编译器) + 脱离 EOL 依赖链 (Vite 5 已停止维护窗口)
- 代码面暴露极小 (breaking 标记全 0), 4-6 人日成本可控, 主要风险是 @types 19 类型长尾
- 触发升级的硬条件: ① 未来要引入 RSC/框架模式 ② antd 6 迁移提上日程 (antd 6 要求 React 19) ③ Vite 5 出现未修复的安全漏洞

> 与能量策略 P1 (8-12 人日) 错峰: 建议能量策略实施期不动前端大版本, 避免双线回归。
