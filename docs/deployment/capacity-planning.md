## 容量规划

### 当前配置承载能力

基于基准测试，当前配置 (2核4G) 可承载:

- **并发用户**: 100-150
- **日活跃用户**: 500-1000
- **日请求量**: 100万-200万
- **数据量**: 站点 50+, 设备 500+

### 扩展方案

#### 水平扩展 (Scale Out)

```
┌─────────────────┐
│   Nginx LB      │
│  (负载均衡)      │
└────────┬────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌───────┐ ┌───────┐
│App-1  │ │App-2  │  ...  ┌───────┐
│(8000) │ │(8001) │       │App-N  │
└───────┘ └───────┘       └───────┘
    │         │              │
    └────┬────┴──────────────┘
         ▼
┌─────────────────┐
│   PostgreSQL    │
│  (主从复制)      │
└─────────────────┘
```

### 性能优化建议

#### 1. 数据库优化

```sql
-- 索引优化
CREATE INDEX CONCURRENTLY idx_devices_station_id ON devices(station_id);
CREATE INDEX CONCURRENTLY idx_alarms_status_created ON alarms(status, created_at);
CREATE INDEX CONCURRENTLY idx_telemetry_device_time ON telemetry(device_id, timestamp);

-- 分区表 (大数据量)
CREATE TABLE telemetry_2026_05 PARTITION OF telemetry
    FOR VALUES FROM ('2026-05-01') TO ('2026-06-01');
```

#### 2. 缓存策略

```python
# Redis 缓存配置
CACHE_CONFIG = {
    "stations": 300,      # 5分钟
    "devices": 60,        # 1分钟
    "stats": 30,          # 30秒
    "alarms": 10,         # 10秒
}
```

## 监控告警

### 关键指标

| 指标 | 警告阈值 | 严重阈值 |
|------|---------|---------|
| CPU | > 70% | > 90% |
| 内存 | > 80% | > 95% |
| 磁盘 | > 80% | > 95% |
| 响应时间 | > 500ms | > 2s |
| 错误率 | > 1% | > 5% |
| DB连接数 | > 40 | > 50 |

### 扩容触发条件

1. **CPU > 70% 持续 5 分钟** → 告警
2. **CPU > 85% 持续 2 分钟** → 自动扩容
3. **内存 > 80% 持续 10 分钟** → 告警
4. **P99 延迟 > 1s** → 告警
5. **错误率 > 1%** → 告警 + 降级
